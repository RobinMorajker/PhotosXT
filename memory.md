# Memory — PhotosXT

Durable facts and decisions that a future session would otherwise have to rediscover. One line each; delete a line when it stops being true. Status and in-progress work belong in `.session/` logs, not here.

## Decisions
- App name is **PhotoXT**; the folder and the Claude project are named PhotosXT.
- Stack: native Android, Kotlin + Jetpack Compose (chosen over Kotlin Multiplatform and Flutter, 2026-11-04).
- Audience: private first (family, up to 100 Google accounts), kept Play Store-ready for a later public launch (2026-11-04).
- SDK levels: minSdk 30 (Android 11), targetSdk and compileSdk 37 (Android 17). Google Play requires target 36+ since 31 Aug 2026.
- Backend: Firebase in asia-south1 (Auth, Firestore, Functions, Hosting, Storage, FCM, App Check). It is used only for public albums, boards, share-link records and invites.
- Drive scopes: `drive.readonly` when the first folder is added, upgrade to `drive` on the first write, `drive.appdata` for settings sync. `drive.file` + Google Picker can't list a picked folder's contents (re-test in the Phase 3 spike).
- Data boundary: Drive content, Drive metadata and OAuth tokens never leave the device. Why: restricted-scope data stored on or sent to servers triggers Google's yearly security assessment.
- Sharing with people uses Drive permissions; the Shared Albums "With me" view reads Drive `sharedWithMe`. Links are Android App Links on the Firebase Hosting domain (Firebase Dynamic Links shut down in Aug 2025).
- Google Cloud for private use: in Testing status, grants expire every 7 days. In production but unverified, users see a warning and the project is capped at 100 users.
- Two editions (2026-11-04): PhotoXTPro is the full spec, including public media boards. PhotoXT is the same spec without media boards; Public Albums stay, since only boards were asked to go. Section and phase numbers match in both specs.
- One codebase for both editions (Robin, 2026-11-04). Build PhotoXT now; add the `pro` product flavor (PhotoXTPro) in this repo when board work starts (Phase 12). No flavors before that.
- Git and CI (Robin, 2026-11-04): this folder is the repo root, branch `main`. The remote `origin` is github.com/RobinMorajker/PhotosXT (Phase 0 pushed by Robin). CI is `.github/workflows/ci.yml` and runs on every push to `main`; the same command runs locally (see README "Build and check"). Sessions commit locally; Robin pushes.
- Toolchain (pinned 2026-11-04 in `gradle/libs.versions.toml`): Gradle 9.8.2, AGP 9.5.0 with built-in Kotlin (never apply `org.jetbrains.kotlin.android`), Kotlin 2.4.21, KSP 2.3.13, Hilt 2.60.1, Compose BOM 2026.09.00 (Material 3 1.4.0), Navigation 3 1.2.0. Builds need JDK 17+; CI uses 21.
- `applicationId` and namespace are the placeholder `com.photoxt.app` until open decision 1 (spec §9) is settled, before Phase 11.
- Navigation: one Navigation 3 back stack per tab, each with its own saveable-state and ViewModel-store decorators, so a tab keeps its state and ViewModels while hidden (nav3-recipes "multiple back stacks"). Back exits through Pictures. An album opens as `AlbumKey` on the Albums stack.
- One UI header: `PxtCollapsingHeader` in core/designsystem on Material 3's exit-until-collapsed scroll behaviour. Expanded = 40% of the window height, collapsed = 64 dp, and no expansion on windows under 480 dp tall. A bottom toolbar row holds the navigation icon, actions and the collapsed title; every header carries the test tag `PXT_HEADER_TEST_TAG`.
- Logging: only `PxtLog` (core/common). It redacts tokens, e-mails, URIs, paths, media file names and coordinates; debug StrictMode reports through it.
- No Android cloud backup or device-to-device transfer (`allowBackup`/`fullBackupContent` false, `data_extraction_rules.xml` excludes everything). Settings restore through the user's Drive app-data folder (spec §4.8) instead.
- Theme: dynamic colour by default; without it, the Material 3 baseline scheme until the accent setting exists (§4.20). AMOLED black is `PxtTheme(amoledBlack = true)` and gets a user setting with the other theme options.
- Icons: Material Symbols Rounded, as vector drawables in core/designsystem (`ic_tab_*`). Not `material-icons-extended`.
- `baselineprofile/` holds both the Baseline Profile generator and the Macrobenchmark startup test (Android Studio's layout); there is no separate `benchmark/` module.
- Quality gates run from the root: Spotless with ktlint `android_studio` style (100 columns, no trailing commas), detekt 1.23.8, and Android Lint with warnings as errors (version-age checks and `ObsoleteLintCustomCheck` disabled).
- Modules added in Phase 1: `core/model` (plain Kotlin types; uses the Android library convention, no Android APIs), `core/database` (Room), `core/media` (MediaStore indexer, access, thumbnails), `feature/timeline` (Pictures and the grid of one album) and `feature/albums`. Hilt modules use the `photoxt.android.hilt` convention plugin.
- Room v1 (Phase 1): `album`, `media` and `media_store_cursor` (per volume: MediaStore version, generation and the time zone of the day keys). Schemas are exported to `core/database/schemas`; every later version needs a migration test.
- Ids: device media `device:<MediaStore _ID>`, device albums `device:<BUCKET_ID>`. `media.dayKey` and `monthKey` are local-calendar keys of `takenAt` (epoch day; year*12+month-1), so SQL can group; a time-zone change rescans.
- Timeline rows come from one UNION query (each date header, then its items) paged by Room with placeholders and jumps, so headers sit at exact positions. `TimelineLayout` (core/ui) is built from the same query's group counts: placeholder spans, fast-scroller labels, select-all counts, and keeping the same photo in view when the grouping changes.
- Pinch density, densest first: year (12 columns), month (9), then days at 7 down to 1 columns; default 4. Wider windows multiply the columns per 360 dp. Kept in saved state only; it persists with Settings (Phase 6).
- MediaStore indexer: per volume, a generation scan of changed items. An id diff (deletions, plus a direct fetch of ids Room has never seen) runs on every return to the foreground, after permission answers and on MediaStore delete notifications; insert and edit notifications skip it. Full rescans only on a new MediaStore version or time zone. A failed query throws instead of looking like "nothing there".
- Device thumbnails: MediaStore's own thumbnail (`openTypedAssetFile` with `EXTRA_SIZE`), decoded by Coil at tile size into software bitmaps; at most 4 provider reads at a time. Nothing is written to PhotoXT's storage. Hardware bitmaps are off in the app's image loader because they made grid scrolling worse on the A15 (see Known limits); a full-size viewer image may opt back in per request.
- Grid gestures live on the grid, not the tiles: tap, long-press, drag-select with edge auto-scroll, and pinch. Tiles only declare semantics (TalkBack open, select, toggle). While selecting, the navigation bar hides and the selection action bar takes its place.
- Selection is a map of id to capture time in the ViewModel (not saved across process death). Share hands up to 500 items to the system share sheet.
- Permissions: READ_EXTERNAL_STORAGE up to API 32, READ_MEDIA_IMAGES/VIDEO from 33, plus READ_MEDIA_VISUAL_USER_SELECTED from 34. Limited access shows a banner with Manage (picker) and Allow all (app settings), because on One UI 8 asking again only offers the picker.
- detekt: LongParameterList ignores composables, MagicNumber ignores enums. Lint wants `toUri()`, so core-ktx is an explicit dependency.
- Tests: Robolectric runs Android 17, which needs `--add-opens java.base/jdk.internal.access` (set in build-logic) and espresso-core 3.7+ (pinned in app). Screenshot goldens live in `app/src/test/screenshots`; re-record with `./gradlew recordRoborazziDebug`. Screenshot tests click with semantics actions, because touch ripples differ between runs.

## Known limits
- detekt 1.23.8, the latest stable, calls Gradle APIs that Gradle 10 removes. Move to detekt 2 once it is stable.
- At 200% text on a 360 dp phone, bottom-bar labels wrap mid-word (Material 3 default). Revisit in the accessibility pass.
- Screenshot goldens were recorded on Linux, as CI runs. If only screenshot tests fail on Windows with tiny text differences, trust CI or re-record on Linux.
- Robin's test phone is a Galaxy A15 5G (SM-A156E, One UI 8 / Android 16), reachable from robin-laptop over wireless adb. Its library holds about 23,800 photos and videos on two volumes (internal and SD card), enough for the 20,000-item checks.
- Grid scroll on the A15 (Phase 1, `ScrollBenchmark`: release build with Baseline Profile, 8 full-speed flings through 23,781 items, 5 runs): frame overrun P50 −0.2 / P90 5.8 / P95 9.6 / P99 22.1 ms with software thumbnails, against 1.6 / 9.4 / 14.2 / 33.9 ms with hardware bitmaps under the same conditions. About 2% of frames miss the app deadline (trace), short of the §5.8 budget of under 1% janky frames, which Phase 15 must meet. Most remaining misses are rows composing mid-fling and the GPU queue being full.
- Benchmarks on the A15: run them detached through WPSC (`am instrument -w -e class com.photoxt.baselineprofile.ScrollBenchmark com.photoxt.baselineprofile/androidx.test.runner.AndroidJUnitRunner`), about 6 minutes. Compare runs only under the same conditions; the phone runs warm after a profile generation.
- Driving the phone through WPSC: run anything long (installs over a slow link, instrumentation) detached, e.g. `Start-Process cmd.exe "/c adb ... > file 2>&1" -WindowStyle Hidden`, then read the file. A command that leaves a child holding the channel's output pipe (adb starting its server) hangs WPSC until that child exits; Cloudflare also cuts requests at 100 s.
- On the phone, `cp` into /sdcard does not reach MediaStore; save test photos with `content call --uri content://media --method scan_file --arg <path>` after copying, as an app would.
- The phone syncs the Projects folder to its SD card, so files under `build/cowork` (test images, screenshots) show up in its galleries; that folder has a `.nomedia` file. Better: exclude `build`, `.gradle` and `.kotlin` in the sync tool.
- Git from a Cowork session: its device shell can't delete files, so git there leaves `.lock` files. Run git on Windows instead, through WPSC (Git for Windows is installed): Phase 1 was committed in the cloud, copied over as a bundle into `build/cowork`, then `git fetch <bundle> main` and `git merge --ff-only FETCH_HEAD` on Windows.
